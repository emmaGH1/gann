# Judge evidence strategy

## Official requirements verified
A bundled plugin.mjs (<=10 MiB), hosted checks, installed-plugin user journey; upload alone is not submission. Complete Submit Project before October 17, 2026 8pm New York. Local tests do not prove hosted network, approval, settlement or delivery. Short demo posted to X is stated on event landing page. Exact numerical judging weights have not been verified; do not invent them.

## Evidence priorities
1. Clear problem in ten seconds: permission to spend does not establish good spending decisions.
2. Genuine sponsor integration: installed Gann plugin -> PayBox proposal/approval -> $0.01 paid deliverable -> result.
3. Distinctive insight: distinguish model decisions from protections the payment platform actually applied.
4. Repeatable, honest demo: single-run journey must work even if no model makes mistakes; optional comparison labelled accurately.

## Reject unsupported claims
No general safe-for-autonomy license, fabricated blocked-money totals, forced model failures, fake transaction receipts, or implied automatic policy edits. Only show PayBox blocked an attempt when platform evidence exists. Controlled sellers are a test arena, not evidence of vulnerabilities in real merchants or PayBox.
